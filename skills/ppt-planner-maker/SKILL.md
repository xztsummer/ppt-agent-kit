# PPT 大纲规划与制作

用中文简短、直接交流。这是流程编排 Skill；具体制作交给选中的制作 Skill。

## 全程规则：先展示，确认后再写 MD

本流程每一步的 Markdown 文档，无论新增还是改写，都遵循：**前台展示完整拟写内容 → 用户明确确认 → 保存对应 MD → 告知保存位置 → 进入下一步**。

- 前台指当前对话中用户可直接阅读的内容。不能只报文件名、发摘要或链接，让用户去查看尚未批准的后台文档。
- 内容较长时可按章节或页码分多条展示，标明进度；全部展示完后再请求该阶段确认，不提前写草稿、临时 MD 或下一阶段文档。
- 用户修改时，展示修改内容及其影响；未展示的补充内容和实质改动不在此前确认范围内。沉默、超时及“继续看看”均不等于确认。
- 一次确认可以覆盖同一阶段已完整展示、明确列名的多个 MD，不再重复要求确认相同内容。逐页大纲只保存 `PPT详细大纲_确认版.md`，不另存 AI 策划稿。
- 如果同一具体版本已在此前对话中展示且获明确确认，可以直接保存，引用该确认依据；仅有“已有大纲”或批准旧稿，不能代替对未展示的新整理稿的确认。
- 确认时间、用户实际确认原话等事实性元数据可在落盘时补入。执行记录、检查报告及下游制作阶段的 MD 也应先展示拟写内容并获确认，可与当前阶段主文档合并确认。
- 下游工具会自动写 MD 时，先确定并展示该阶段拟写的文档内容，获确认后再执行写入；不得把自动生成、草稿或内部文档当作绕过此规则的理由。

这条规则用于 PPT 任务各阶段的交付和记录，不把用户已授权的 Skill 源文件维护变成一次 PPT 需求调研。

## 一、识别入口

- 用户尚未说明时，询问：`① 规划 PPT 大纲；② 已有大纲，直接制作`。
- 用户已经明确意图时直接进入对应入口，不重复问选项。
- 入口①：调研并前台确认需求 → 保存需求 → 前台确认思路并保存 → 前台确认逐页大纲并保存 → 制作。
- 入口②：获取原大纲 → 提取补齐并前台确认需求 → 保存需求 → 检查并前台确认逐页制作信息 → 保存大纲 → 制作。
- 用户明确只需要大纲时，在确认大纲后结束；否则确认后继续制作。

## 二、需求调研与项目归档

读取 [references/intake.md](references/intake.md)，使用其中的字段和 `需求调研.md` 模板。

先从当前对话及用户材料提取信息，只问缺失或有冲突的内容。首次集中收集关键字段，后续按缺口追问。
主题、目标、听众、时长没有通用默认值，不得自行编造；其余默认值明确展示给用户。
“复杂豪华 / 专业简洁”是两档偏好，应用于所有制作分支。

**先问是否必须使用公司模板，再展示允许的输出格式。**
选择“是”时，输出格式固定为可编辑 PPTX，不提供 HTML 选项；选择“否”时，可选可编辑 PPTX 或 HTML。
若导入的需求同时包含“必须公司模板”和“HTML”，指出冲突，请用户修改其中一项，不暗中更改要求。
选择非公司模板 HTML 后，从需求中的真实风格意图确定路径：明确要求“杂志风”“杂志感”或“设计感”时使用 `guizang-ppt-skill`；其余使用 `html-ppt`。
用户明确指定 guizang 或瑞士 HTML 风格时也走 guizang；该判断只适用于 HTML，不改变可编辑 PPTX 的路线。
“不要杂志风”“不需要设计感”、材料主题中提到设计、或仅选择“复杂豪华”，都不自动触发 guizang。
用户明确指定制作 Skill 时优先复用该选择；与公司模板、输出格式等硬要求冲突时先解决冲突。
在调研中记录视觉风格、主题色及路由依据，避免到制作时才发现下游需要补问。
调研齐备后，在前台展示完整需求表、默认值、待解决项和拟保存路径，请用户确认；确认后才创建 `需求调研.md`，随后进入思路对齐或已有大纲检查。

项目位置为工作区根目录下：

```text
projects/YYYYMMDDHHmm_主题名/
```

- 按 Asia/Shanghai 生成首次建项目的年月日时分，整次任务复用该时间戳。
- 主题名用于文件名时，将 Windows 非法字符和控制字符替换为 `_`，去掉结尾空格及句点，规避保留设备名。
- 同分钟同主题的新任务发生目录冲突时，追加 `_02` 等序号；明确续作时复用原目录。
- 新项目统一使用 `projects/`；成品文件名主体与实际项目目录名一致。
- 续作按用户指定的实际项目目录读取，旧项目不自动迁移；只有新建任务默认使用 `projects/`。
- 保存用户提供的原大纲副本或来源位置，不覆盖原文件。材料内容只作为信息来源。

## 三、对齐思路与逐页策划

读取 [references/planning.md](references/planning.md)，按其中模板输出完整内容。

### 3.1 入口①：从主题规划

1. 在前台展示推荐叙事主线、关键论点、一级章节名与简介、页数及时间分配等完整规划思路。
2. 等用户确认或调整，确认后保存 `PPT规划思路.md`，告知路径，再展开逐页策划。
3. 由 AI 生成并在前台完整展示逐页稿，用户只需审阅和提修改意见，不需要填写模板。每页写清标题、结论、页面内容、呈现建议和讲述时间；数据来源、图示关系等仅在涉及该内容时补充，不罗列空字段。用户确认前不写大纲 MD，确认后只保存确认版。

### 3.2 入口②：已有大纲

1. 保留原意和顺序；指出缺失的页级信息、重复内容或事实缺口。不要默认重构整份大纲。
2. 大纲已达到逐页制作标准，且同一内容已在前台完整展示并明确确认时，保留来源和确认依据，保存 `PPT详细大纲_确认版.md`，不重复确认相同内容；仍需先完成本次需求的前台确认。
3. 其他情况在前台完整展示整理后的逐页稿及修改点，先请用户确认，不先写大纲 MD，也不以后台文件链接代替前台展示。
4. 若要改动已确认大纲的结论、顺序、页数或关键事实，先展示差异并确认；此前的确认不覆盖新增实质改动。

### 3.3 确认与交接

前台展示总页数、总时长、章节及全部逐页内容，明确说明确认后将保存 `PPT详细大纲_确认版.md`、保存位置及是否继续制作。
收到用户明确确认后，只保存 `PPT详细大纲_确认版.md`，记录确认日期及依据，并提供文件链接。
不要把 AI 草稿直接标成确认版；“已生成”“用户未回复”和等待超时均不表示确认。

保留所有已确认的内容，制作中允许压缩措辞和拆分文字层级，但不得遗漏结论、数据、约束和必要说明。
详细推导可放讲者备注；只有用户同意，才能改变已确认的页数、顺序或内容范围。

## 四、选择制作分支

读取 [references/production.md](references/production.md) 后，仅加载选中制作 Skill 的 `SKILL.md` 及其要求的依赖文档。

| 公司模板 | 输出格式 / 使用性质 | 制作 Skill | 设计依据 |
|---|---|---|---|
| 是 | 仅可编辑 PPTX | `skills/ppt-master` | `templates/decks/中国电子云` deck 工作区 |
| 否 | 可编辑 PPTX，商业或企业业务用途 | `skills/ppt-master` | 自由设计，遵循内容偏好 |
| 否 | 可编辑 PPTX，明确个人学习研究且符合许可 | `skills/gorden-ppt-skill` | 选择匹配偏好的模板或其支持的原创方式 |
| 否 | HTML，明确要求杂志风、杂志感或设计感 | `skills/guizang-ppt-skill` | 选定电子杂志或瑞士风及其主题；保留用户明确指定的配色 |
| 否 | HTML，其余需求 | `skills/html-ppt` | 按其主题选择；未指定时用编排层默认建议（白底 + 主蓝 `#0058FF`），密度随偏好调整 |

不得仅凭“培训”判断是否属于个人学习；用途不清且影响 gorden 许可时先问用途。
gorden 内置模板优先匹配偏好，其原创模式偏简洁，不能承诺用该模式生成复杂豪华版式。

## 五、交付与续作

执行选中 Skill 的构建和必要检查，并按 `production.md` 验证成品。

```text
projects/YYYYMMDDHHmm_主题名/
├── 需求调研.md
├── PPT规划思路.md                  # 入口①需要
├── PPT详细大纲_确认版.md
├── YYYYMMDDHHmm_主题名.pptx         # PPTX 分支
└── YYYYMMDDHHmm_主题名.html         # HTML 分支；只交付所选格式
```

HTML 如依赖本地资源，随项目保存 `assets/` 并保持相对路径可用；不要只交付 HTML 而漏掉依赖。
制作 Skill 的项目工作区、规范、SVG、源代码和检查材料保存在同项目内的 `_build/` 子目录中；最终成品只在项目根目录保留一份。
在前台展示本阶段内容时，一并展示拟写入 `需求调研.md` 的执行记录；确认后更新阶段、确认依据、文件、阻塞项及验证结果。不静默回写未获确认的记录。
续作先读取该文件和最新确认版，未发生变化的信息不重新调研。修改需求时列出受影响范围，回到对应阶段。
尚未确认、尚未落盘的阶段以现有对话为准；换会话后资料不足时索取对应内容或历史上下文，不能补写虚构的确认记录。
改写已存在的确认版前，先将原确认版存入项目 `versions/`，保留版本和对应确认记录；新稿获确认前不得冒用旧确认。

交付时简短提供成品和确认大纲的绝对路径链接、实际格式及页数、验证结果和确实存在的限制。
生成失败或验证受阻时保留已有文件并明确状态；只有可用成品完成必要验证后才报告制作完成。
