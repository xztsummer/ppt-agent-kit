# PPT 制作与交付

## 一、交接契约

开始制作前具备以下文件和决定：

1. `需求调研.md`：核心必填项齐全，输出格式与模板要求无冲突。
2. `PPT详细大纲_确认版.md`（入口①②）或 `修改方案_确认版.md`（入口③）：包含完整逐页内容/修改清单，以及有效确认依据（快速模式下为授权依据）。
3. 事实、图表数据与必需图片已就绪，或用户已经同意具体的删改与替代。
4. 已解析的制作 Skill 绝对路径、模板根路径、制作工作区目录和最终成品路径。
5. HTML 已根据视觉风格选定路径；guizang 的 A/B、主题和正式演讲时间预算已确定。
6. 以上 A 类文档均已先在前台展示，获用户确认后落盘；不能把后台生成的文档当作已完成前台确认。用户授权快速模式时，按 [confirmation.md](confirmation.md)「快速模式」：合并确认的依据是那一次整体确认，授权直出的依据是授权原话，文档已在对话中展示即可进入制作。
7. 入口③：源 PPTX 已有只读副本，修改方式、范围、必须保留项和 `修改方案_确认版.md` 已确认；未改动页已列明，或已说明 Beautify 全量重设计的保留规则。

技能根路径相对于**目标工作区**的 `skills/` 解析，不相对于本编排 Skill 的 `references/`，也不写死绝对路径。
目标工作区取本次任务实际读写的工作区根目录（即 `projects/` 所在目录）；不确定时向用户确认，不猜测。
只有选中分支需要其制作依赖；缺少其他分支的依赖不妨碍当前任务。
若选中依赖不存在，说明缺少的具体路径，索取可用位置；不要悄悄切换其他制作 Skill。

调用是加载并执行选中制作 Skill 的 `SKILL.md`，不默认启动子代理或另建聊天：

- **同会话执行（默认）**：把下方清单作为内部交接核对项逐条对齐，**不在对话中向用户打印这段文字**。
- **子代理执行（仅在需要隔离上下文而启动子代理时）**：把下方清单替换为实际值后，连同下方“制作与交接约束”一起作为子代理的任务描述发送。

```text
需求文件：{绝对路径}/需求调研.md
完整确认大纲/修改方案：{PPT详细大纲_确认版.md 或 修改方案_确认版.md 的绝对路径}
目标：{目标}
听众、场景、时长：{需求值}
内容偏好：{复杂豪华 / 专业简洁}
视觉风格、主题及颜色：{用户原始要求；guizang 的 A/B 与主题；html-ppt 已确认的默认建议或所选主题}
路由依据：{用户的模板、使用性质或 HTML 风格要求}
时间预算：{逐页讲述合计、互动/问答、缓冲、总时长及问答口径}
输出格式：{可编辑 PPTX / HTML / PPTX + HTML 双格式}
确认方式：{逐阶段确认 / 合并确认 / 授权直出：用户原话}
制作 Skill 根目录：{已验证的绝对路径}
模板：{中国电子云 deck 根目录 / 用户指定模板 / 自由设计 / HTML 风格 / 源 PPT 原生设计}
项目目录：{绝对路径}
制作工作区：{绝对路径，默认 {项目目录}/_build/<skill 名>/}
最终成品路径：{项目根目录下的标准路径 `{项目目录}/{项目目录名}.pptx/.html`；若用户额外指定输出路径/文件名则一并列出}
源 PPTX / 修改方案 / 修改方式 / 必须保留（仅入口③）：{对应值 / 不适用}
```

制作与交接约束：
- 入口①②采用确认稿的完整内容、页序和页数，保留全部结论、数据和必要说明；文字压缩和视觉编排以可读性为准，文本与约定图表/表格必须可编辑。
- 入口③按修改方案执行：未列入清单的页面、文字、数据、品牌元素和页序保持原样，不得覆盖源文件。
- 中间产物保存在 `_build/<skill 名>/`（ppt-master 用其项目初始化的基础目录参数建在该工作区内，不在项目根目录直接初始化）；构建完成后将最终成品复制为项目根目录下的标准路径（以及用户额外指定的输出路径），`exports/`、`validation/` 留在工作区作检查证据。
- 已经明确的需求直接复用，不重新完整调研；制作 Skill 另有确实未回答的设计问题或必要确认时，只问剩余部分。
大纲确认不能冒充后续设计方案的确认，也不自动授权跳过所选 Skill 的阻塞检查。
不要把“已有完整确认大纲”理解成“用户要求 Quick”或“跳过策略”的指令。本编排层的快速模式也不等于下游 Skill 的 Quick 模式；授权直出时，下游的设计偏好询问由 AI 按已记录的决定作答，阻塞检查照常执行（范围见 confirmation.md「快速模式」）。
下游模板不能承载已确认的页数、数据或必要图示时，说明具体差异并回到策划确认，不默默删页、删数据或替换制作路线。
下游会自动写 Markdown 的命令：写 A 类文档前按规则展示确认；只写引擎内部产物时可直接执行并在阶段结束汇报。无法区分时先说明限制并等用户决定。

## 二、分支规则

### A. 必须使用公司模板：ppt-master

- Skill：`{工作区}/skills/ppt-master/SKILL.md`。
- 默认 deck 根：`{工作区}/skills/ppt-master/templates/decks/中国电子云`。
- 传入完整 deck 工作区根目录，不能只传内部 `templates/`，也不能把 `exports/` 中的预览 PPTX 当成唯一制作源。
- 当前模板已包含 `templates/design_spec.md`、五类 SVG 页面和 `images/` 资源，且已登记在 `decks_index.json`。
- 默认是 Generate PPTX，采用提供的 deck 模板；准确路由和前置检查以 ppt-master 当前入口及 `workflows/routing.md` 为准。
- 按其要求执行归属校验、路由、规划、构建与导出，不在本 Skill 中复制底层命令。
- 封面、目录、章节、正文和结束页遵循品牌规范；“复杂豪华”只能在品牌允许范围内体现层次和信息密度。
- 若用户明确指定另一公司模板，用用户模板替代默认 deck，依其实际格式选择合适路由；不修改原始模板。
- 输出固定为 `{项目目录}/{项目目录名}.pptx`，不提供 HTML 选择。ppt-master 只导出到其工作区的 `exports/<项目名>_<时间戳>.pptx`，完成后复制为上面的成品路径。

### B. 非公司模板 + 商业/企业业务 PPTX：ppt-master 自由设计

- Skill：`{工作区}/skills/ppt-master/SKILL.md`，Generate PPTX / free_design。
- 不加载中国电子云品牌模板，不把 HTML 分支的固定配色扩展为该分支的硬限制。
- 复杂豪华：更丰富的信息层级、图示、对比及精致视觉，仍以可读性为准。
- 专业简洁：清晰主张、适量信息、克制配色与留白，必要的架构和流程关系仍应完整。
- 输出为 `{项目目录}/{项目目录名}.pptx`，同样从 ppt-master 的 `exports/` 复制得到。

### C. 非公司模板 + 个人学习研究 PPTX：gorden-ppt-skill

- Skill：`{工作区}/skills/gorden-ppt-skill/SKILL.md`。
- 本地该 Skill 明确限制商业用途。只有用途明确符合其许可时进入该分支；不凭“培训”“交流”等场景名推断个人用途。
- 本项目已约定：企业汇报、客户提案等业务用途走分支 B；用户未明确说明个人学习研究时，默认按商业或企业业务走分支 B（该默认已在需求确认中展示）。
- 读取其当前入口，遵循其更新机制、模板选择、制作及检查流程，不在编排阶段提前更新依赖文件。
- 先按内容偏好选择匹配模板；需要选择时按该 Skill 展示预览并询问用户。
- 该 Skill 的原创方式限定简洁设计，不能默默用于兑现复杂豪华要求。没有合适模板时说明差异并请用户选更换模板、改用 ppt-master 自由设计或接受简洁方案。
- 同时更新图表数值与图形含义；不把装饰性百分比图当成可以随数值变化的原生图表。
- 输出为 `{项目目录}/{项目目录名}.pptx`。

### D. 非公司模板 + 常规 HTML：html-ppt

- Skill：`{工作区}/skills/html-ppt/SKILL.md`。
- 未命中 guizang 的真实风格要求、也未明确指定其他制作 Skill 时使用此路径。
- 主题选择：html-ppt 有 36 套主题，其 `base.css` 默认主蓝是 `#3b6cff`，`#0058FF` 不是它的默认色。用户未指定时，在需求调研阶段就在“视觉风格与配色”字段中填入本编排层默认建议“白底 + 主蓝 `#0058FF`（科技蓝）”并附 2–3 套场景备选主题，随需求表一次确认；用户未修改即按默认建议执行，制作阶段不再二次追问。
- 用户已选主题或配色时原样保留，不静默替换其 token；确需覆盖主蓝时在项目内覆盖主题变量，并把最终配色写进需求记录；不直接修改制作 Skill 的共享 CSS 或模板资源。复杂豪华采用更丰富的图示和信息组织，专业简洁采用留白和精炼表达。
- 使用该 Skill 的页面布局和放映能力。演讲、培训等需要讲者提示时，按其规范处理备注和演讲者视图。
- 输出为 `{项目目录}/{项目目录名}.html`。不要把 HTML 改名成 `.pptx`，也不要声称它是可编辑 PowerPoint。
- 可以内联资源形成单文件；如使用独立资源，应复制到项目 `assets/`，以相对路径引用，确保移走整个项目文件夹后仍可打开。
- 不把主题切换或模板默认色留成可覆盖确认配色的最终状态；预期断网放映时验证系统字体回退和本地资源。

### E. 非公司模板 + 杂志风或设计感 HTML：guizang-ppt-skill

- Skill：`{工作区}/skills/guizang-ppt-skill/SKILL.md`。
- 对用户提出的风格要求判断意图：明确要求“杂志风”“杂志感”或“设计感”即进入；“不要杂志风”“不需要设计感”、只是举例、只在素材主题或文档正文里出现这些词，以及单独“复杂豪华”都不触发。明确指定 guizang 或瑞士 HTML 风格也可进入。
- 只说“高级”“好看”“专业”不足以触发。用户明确指定 html-ppt 时复用其选择，不被风格关键词覆盖；与格式/模板硬要求冲突则先解决冲突。
- 电子杂志 A 和瑞士风 B 只能选一种：明确要求“杂志风”记为 A，明确要求“瑞士风”记为 B，已明确的选择直接复用；仅有“设计感”时，结合主题推荐 A/B，并在需求调研阶段与主题色一起补问一次，不重新调研目标和听众。
- 按 guizang 当前入口执行更新检查、模板和主题选择；该 Skill 的更新需要用户确认，拒绝或无法检查时按其规则继续现有版本，不擅自改写安装文件。
- 采用其主题库，不继承 html-ppt 分支的白底/#0058FF 编排层默认值。用户明确指定必须保留的颜色优先传入并落实；若确实无法兼容，说明影响并补问，不能静默换成预设色。
- 正式演讲使用确认稿的页面目的、讲者要点、转场和稳定页面 ID；逐页讲述预算最多占可用演讲时长 90%，计入的问答/互动和缓冲单独列出。不得直接把每页原时长缩短后冒称仍是已确认内容。
- 图片/截图已有用途、比例及保真要求时直接复用；仅补问缺口。缺少必需素材时不能用未说明的占位图冒充成品。
- 大量表格或密集培训内容与该 Skill 的适用范围冲突时，指出具体页面的问题，询问调整表达还是更换路线，不为风格擅自删内容。
- 模板默认的 `项目/XXX/ppt/index.html` 仅是该 Skill 的示例位置；本次最终入口统一写到 `{项目目录}/{项目目录名}.html`。外置图片放同项目 `images/` 并同步相对路径，不另建第二套项目目录。
- 单文件 HTML 不等于离线无依赖；按需处理字体、图标、动效的外部依赖，只有实际验证后才承诺离线放映。

### F. 现有 PPTX 修改/美化：ppt-master Edit Native / Beautify

- Skill：`{工作区}/skills/ppt-master/SKILL.md`。
- 仅处理入口③，输出固定为可编辑 PPTX；不重做叙事，不换输出格式。
- 源文件先复制到 `{项目目录}/sources/`（保留原文件名），只读保留并记录指纹（按 edit.md）；成品写到 `{项目目录}/{项目目录名}.pptx` 或用户指定路径，绝不覆盖源文件；交付前后各核一次指纹。
- 保留原版式增量编辑：使用 ppt-master 的 Edit Native PPTX 路由，按确认的逐页修改清单改文字、补页、加备注/动画；未列入清单的页保持原样；增删/重排页必须在修改方案中列明并确认。
- 保留内容重新设计：使用 ppt-master 的 Beautify 路由，保持已确认的内容、页序、页数和结论，只改变视觉表达；需要改内容或页序时转入口②。
- 用户要求换成公司模板时，按入口②提取大纲并走分支 A；不在入口③里直接把原页套模板。
- 传入源 PPTX、`需求调研.md`、`修改方案_确认版.md` 和必须保留项；要求下游保留未列入清单的页面、文字、数据、品牌元素、页序和备注（Beautify 全量重设计时保留内容、页序、页数和数据）；修改页的文字必须可编辑。
- 无法保留必须保留项或源设计时，说明具体页码、差异、原因和影响，回到修改方案确认，或请用户在 Beautify、重做、改用其他 PPTX 编辑方式之间选择；不静默替换、删除或降级。
- 检查按「三、成品检查」中的“入口③额外检查”执行。

## 三、成品检查

先执行制作 Skill 要求的检查，再核对交付内容。检查失败后修复对应内容并重跑受影响检查。
不要把可选的专项复查当成所有任务必经的新阶段，也不要因检查工具缺失就宣称检查通过。

共同检查：

- 页数、页序、标题、结论、数据与确认稿一致（执行记录中已登记的交付后微调除外），章节及目录对应。
- 真实数据、单位、统计日期和引用准确，无未经说明的编造、示例数据或遗漏。
- 没有模板示例文字、失效素材、意外占位符；需要用户补齐的关键内容尚未解决时，不标成最终成品。
- 字体、主色、页面层级一致；无明显文字溢出、遮挡和裁剪错误。
- 路径、文件名、扩展名符合需求，承诺的成品路径上确实存在最终文件；只读模板与用户原文件保留。

PPTX 检查：

- 文件可以被 PowerPoint/WPS 或可用的 PPTX 解析器打开，幻灯片数与确认稿一致。
- 检查内部文本及对象，确认主要文字为真文本，而非每页一张整图；确认稿要求的图形、表格及图表按约定可编辑。
- 用可用渲染器生成页面预览并查看，检查实际排版；结构解析不能替代视觉检查。
- 渲染器不可用时明确报告“结构检查通过，视觉检查未完成”，保留成品及源文件，不报告全部验证完成。

入口③额外检查（以 `修改方案_确认版.md` 代替“确认稿”）：

- 页数、页序、标题与修改方案一致；改动页的文字、数据、品牌元素符合逐页修改清单。
- 对比源文件与成品：未列入清单的页无意外变化（按标题和内容识别，不只看页码）；Beautify 全量重设计时，核对内容、页序、页数、数据和结论不变，视觉变化符合修改方案。
- 必须保留项齐全；修改页没有文字丢失。
- 交付前重算源文件指纹，与 `修改方案_确认版.md`「任务信息」记录的一致性有明确结论（一致 / 不一致+差异说明），原件未被覆盖或改写。

HTML 检查：

- 在真实浏览器打开成品，检查所有页面及资源加载；不要仅检查源代码。
- 验证前后翻页、首尾页、全屏入口，以及实际使用的目录或演讲者视图；浏览器限制存在时如实记录。
- 按实际确认的分支主题检查：html-ppt 按已确认主题（未指定时按需求确认的科技蓝默认建议），guizang 按选定 A/B 与主题，用户指定配色均须保留；检查可读性和目标显示比例，无明显越界、遮挡或遗漏。
- 成品入口和资源相对路径可用；若宣称离线可用，应实际断网或阻止外部请求验证。

最后按 SKILL.md 的“阶段汇报”格式，在前台展示检查范围、实际结果、未完成项和交付摘要；执行记录直接写回 `需求调研.md`，检查报告等内部产物留在 `_build/`。涉及需求、范围、结论或成品内容变化时，先确认。
不要把创建了文件、命令退出码为零或通过 Skill 格式校验，当成成品已验证。
