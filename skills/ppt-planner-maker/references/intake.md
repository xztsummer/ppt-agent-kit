# 需求调研

## 提问规则

先提取，再补问。已有大纲可以说明主题和章节，但通常不能可靠推断目标、听众及演讲时长。入口③的源 PPTX 可以说明现有页数、页序和部分内容，但不能可靠推断新的目标、听众和修改范围。
把字段标为“用户明确 / 材料提取 / 默认 / AI 建议 / 待补充”，不要把猜测当成用户要求。

| 字段 | 要求 | 选项或默认值 |
|---|---|---|
| 主题 | 必填 | 无默认值 |
| 使用场景 | 必填，有默认值 | 方案汇报（默认）、工作汇报、客户交流、演讲、培训、其他 |
| 是否必须使用公司模板 | 必填，有默认值 | 是（默认）/ 否 / 待定（仅大纲时）；本项目默认模板：中国电子云。用户明确要求 HTML 且未点名公司模板时取“否”，两者都明确要求时按冲突处理 |
| 内容偏好 | 必选，有默认值 | 复杂豪华（默认）/ 专业简洁 |
| 输出格式 | 必选，受模板约束 | 公司模板：固定可编辑 PPTX；非公司模板：可编辑 PPTX（默认）/ HTML / 同时交付 PPTX 与 HTML（仅用户明确要求时）；只要大纲时记“待定” |
| 使用性质 | 仅非公司模板 PPTX 必填，有默认值；公司模板 / HTML / 入口③ 记“不影响所选路线” | 商业或企业业务（默认，走 ppt-master）/ 个人学习研究（符合许可时可走 gorden）/ 不影响所选路线（公司模板、HTML、入口③） |
| 视觉风格与配色 | 按需提取或补问 | 与复杂/简洁的密度偏好分开记录；非公司模板 HTML 据此判断是否走 guizang；走 html-ppt 且未指定配色时，在需求表中填入默认建议“白底 + 主蓝 #0058FF（科技蓝）”并附 2–3 套备选主题供随表确认 |
| 目标 | 必填 | 希望听众听完理解什么、认可什么、决定什么或采取什么行动 |
| 听众 | 必填 | 身份、关注点、主题熟悉程度；只补问影响策划的部分 |
| 时长 | 必填 | 正数，单位分钟；必要时明确是否包含问答 |
| 目标页数 | 选填 | 未指定则 AI 按内容、时长建议；明确总页数是否包含封面及章节页 |
| 背景及注意事项 | 选填 | 业务背景、必讲/禁讲内容、敏感信息、口径、日期、语言、品牌要求 |

“必填且有默认值”表示必须形成明确记录，可以使用已展示的默认值。无需逐字段确认；需求补齐后，前台展示完整需求调研内容，并一次确认本阶段文档后再保存。

## 入口③：修改/美化现有 PPTX

入口③复用主表的主题、目标、听众、时长、视觉风格等字段；源文件、修改方式、修改范围、必须保留项、可改动项、验收标准和输出文件，以 [edit.md](edit.md)「需求字段」为准。入口③输出固定为可编辑 PPTX，不展示 HTML 选项，也不询问公司模板。

用户希望一次性填写时，用下面的短表单；如果已有信息则预填，并将 HTML 选项只展示给非公司模板用户。

```text
主题：
使用场景：方案汇报 / 工作汇报 / 客户交流 / 演讲 / 培训 / 其他（默认：方案汇报）
必须使用公司模板：是 / 否（默认：是，中国电子云）
内容偏好：复杂豪华 / 专业简洁（默认：复杂豪华）
输出格式：[公司模板固定为可编辑 PPTX；选择非公司模板后可选 PPTX / HTML]
使用性质：[仅非公司模板 PPTX] 商业或企业业务 / 个人学习研究（默认：商业或企业业务）
视觉风格与配色：有指定则填写；HTML 如希望杂志风或设计感请注明
希望达成的目标：
听众：
时长：__ 分钟
目标页数：可留空，由 AI 建议
背景及注意事项：可留空
```

入口③在短表单外，另按 edit.md「需求字段」填写入口③专属字段。

附加信息按需获取，不增加一串无关必填项：

- 已有大纲制作：请用户提供粘贴文本或文件路径；支持的文件类型由当前读取工具决定。
- 修改/美化现有 PPTX：源文件处理、修改方式和解析结果展示，按 edit.md 执行。
- 需要事实、指标、案例时：询问现有材料和可引用来源；缺失的数据不得编造。
- 非公司模板 PPTX：从目标和背景识别商业 / 企业业务或个人学习研究；不凭“培训”“交流”等场景名推断个人用途。用户未明确说明个人学习研究时，默认按商业或企业业务走 ppt-master，并在需求表中标为“默认”，用户可修改；不为此单独追问。
- 非公司模板 HTML：记录用户关于风格的原话、明确指定的颜色和图片/截图要求，供路由判断并原样交接。html-ppt 与 guizang 的路由、guizang 的 A/B 判断与配色规则，以 [production.md](production.md) 分支 E 为准；需要补问 A/B 时，在需求调研阶段一并问。
- 用户说必须使用“另一家公司模板”时，先索取指定模板，不能擅自套中国电子云。
- 目标时长与页数明显冲突时，解释节奏影响，提出推荐调整，请用户决定。
- 缺少补充信息时可继续前台整理和补问，不能为了归档而先写未获确认的需求 MD。关键必填项补齐、完整需求前台展示且用户确认后，才保存并进入下一阶段。

## 需求确认与落盘

按照下方模板在对话中展示项目信息、已知需求和原始材料（包括来源、默认值、已知冲突和拟保存目录）；`## 执行记录` 在落盘时由 AI 自动写入，不在对话中展示。
入口③将需求表与 `修改方案_确认版.md` 一起展示，源文件、修改方式、范围、必须保留项等任务信息写在修改方案中，不在需求调研里重复。
先问“以上需求是否确认？确认后保存 `需求调研.md`，再进入{思路对齐/已有大纲检查/修改方案确认}”。入口②（大纲已齐备）或入口③若需求与逐页大纲/修改方案已一起完整展示并明确列名，可一次确认并同时保存。用户确认后落盘并告知路径。
用户直接给了完整需求也不代表已确认 AI 整理的未展示内容；已在前台展示并明确批准的同一版本可复用确认，无需重问。
确认记录可在落盘时补入实际确认时间和原话。默认值、推断及资料提取须在确认前就对用户可见。
用户授权快速模式时，按 [confirmation.md](confirmation.md)「快速模式」执行：合并确认时，需求与后续文档一起展示、一次确认；授权直出时，展示需求表后不等待确认，直接保存，缺失的目标、听众、时长标为“AI 建议”，确认依据记为授权原话。
