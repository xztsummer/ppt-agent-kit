# 思路对齐与逐页策划

## 叙事选择

先回答：这份 PPT 要让哪些人，基于哪些证据，形成什么判断并采取什么行动？
推荐最适合当前目标的主线，不必强行套同一种章节结构：

| 场景 | 可用主线 |
|---|---|
| 方案汇报 | 现状与问题 → 目标及约束 → 解决方案 → 价值与证据 → 实施路径 → 决策请求 |
| 工作汇报 | 目标与结果 → 关键工作及证据 → 差距与原因 → 下一步计划 → 所需支持 |
| 客户交流 | 客户关注与痛点 → 能力映射 → 场景方案 → 价值证据 → 合作下一步 |
| 演讲 | 核心观点 → 问题或冲突 → 推导与案例 → 结论与行动 |
| 培训 | 学习目标 → 知识框架 → 分步示例 → 练习或检查 → 总结与迁移 |

这些是起点。章节数、页数及标题根据材料决定，不为凑结构而添加无证据的内容。
论证顺序服务听众决策；一级章节名具体、互不重复；章节简介说明解决什么问题。

章节表必须覆盖完整正文；额外封面、目录、章节页、结束页等单独计入页数和时间。

时间须满足“逐页讲述时长合计 + 计入本次时长的互动/问答 + 缓冲 = 约定总时长”，不能把留缓冲误判为少内容。
guizang 正式演讲按其规则把逐页讲述控制在可用演讲时长的 90% 以内，余量记录为互动或缓冲；单独约定、不计入演讲的问答不混入分母。
已有确认稿用满时长时，不静默缩短或增加时间；展示节奏调整并取得确认后再改。

## 逐页大纲模板

**由 AI 生成，不让用户填表。** 用户只需阅读、提出修改意见或确认。
使用下面的简洁格式，在前台逐页展示完整内容；确认后只保存为 `PPT详细大纲_确认版.md`，不另存 AI 策划稿。
需求、听众、制作路线等已在 `需求调研.md` 中记录，不在大纲里重复铺一遍。

```markdown
# {主题}｜PPT 逐页大纲

共 {页数} 页，总时长 {分钟}（讲述 {分钟}，互动/问答 {分钟}，缓冲 {分钟}）。
整体风格：{一句话说明}。

## 第一章：{章节名}

### P01｜{页面标题}
- 本页结论：{希望听众记住的一句话}
- 页面内容：
  - {可直接放上页面的具体内容}
  - {可直接放上页面的具体内容}
- 呈现建议：{例如：左侧三个问题，右侧用流程图解释；说明具体图示关系}
- 讲述时间：{秒}

{按同样格式写完每一页；按实际需要分章，不要求凑固定章节数或要点数。}
```

仅在需要时，在对应页追加简短说明：

- 有数据或案例：列出具体数据、单位及真实来源；有统计日期或口径要求时一并写明。
- 有图表或架构图：写出图表数值、节点及关系，不能只写“画一个架构图”。
- 有指定图片或截图：注明素材位置、用途及必要的保真要求。
- 有额外讲解或特殊可编辑要求：简短补充，避免把讲稿全部挤上屏幕。
- 有待补信息或修改：只列真实存在的问题及影响，没有就省略。

不要逐页机械填写“无 / 不适用”，也不要增加重复的页面总览、标题副本和内部检查表。
封面、目录及过渡页按实际用途描述，不强行编写结论或多条正文。
保存时在文末补充实际确认日期和用户确认依据，不增加未经展示的新内容。

## 确认前检查

- AI 自行核对页码连续、实际页数与开头一致、章节名称前后相符，不要求用户填写检查表。
- 每页正文、数据和图示关系足以制作，不以“后续补充”替代必须内容。
- 按讲述、互动/问答及缓冲核对总时长，guizang 正式演讲另核对讲述预算。页数可以建议，调整已确认页数须先告知并确认。
- 所有事实与真实来源一致；未来设想、估算或建议须明确标注。
- 关键事实缺失时先补齐或请用户同意删除相关论断，再确认。演示示例须明确为示例且获用户同意。
- 公司模板要求与输出格式相容；内容偏好已经落实到页面规划。

对用户前台展示以上简洁大纲的完整内容，以及确实需要用户决定的事项和拟保存路径。长稿可分批展示，不能只展示摘要或以文件链接代替全文。
请求确认应说明：“确认后保存 `PPT详细大纲_确认版.md`，并按此完整大纲开始制作”；若用户先前明确只要大纲，则说明保存后结束，不继续制作。
确认后再提供已保存的文件链接。写入的正文必须与用户确认版本一致。
