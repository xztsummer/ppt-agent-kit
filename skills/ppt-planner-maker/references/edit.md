# 修改/美化现有 PPTX

入口③专用。源文件是 `.pptx`，用户要改内容、改几页、补备注/动画或重新设计版式；不重新策划叙事。

流程：源文件处理 → 确定修改方式 → 补齐需求字段 → 展示需求与逐页修改方案 → 确认并保存 → 交接制作与检查（按 production.md 分支 F）。

## 适用与不适用

适用：

- 保留原版式，改文字、数据、局部版式、图片或备注/动画。
- 保留内容，重新设计视觉版式。
- 按现有公司模板重做版式，但内容来自源 PPT（按入口②重做，不在入口③内直接套模板）。

不适用：

- 内容结构、页序或结论要大改 → 入口②，把 PPTX 当材料提取大纲；若同时要求保留原版式，先评估 Edit Native 能否承载，不能承载时说明差异并请用户选择。
- 要输出 HTML、PDF 或其他格式 → 入口②对应分支。
- 用户只给了 PPTX 截图或 PDF，没有 `.pptx` → 只能作为材料，按入口②重新制作；不要声称在做原生编辑。
- 旧版 `.ppt` → 先尝试转换：本机有 LibreOffice 时执行 `soffice --headless --convert-to pptx --outdir {项目目录}/sources {原文件}`（Windows 上 `soffice` 不在 PATH 时，常见路径为 `C:\Program Files\LibreOffice\program\soffice.exe`）。转换可能丢失动画、字体或版式细节，须先向用户说明，并展示转换后的解析结果，用户同意后再按入口③继续；原 `.ppt` 同样保留在 `sources/`。没有转换工具或转换失败时，按入口②作为材料重做。

## 修改方式

只在用户意图不明确时问一次：

| 方式 | 判断 | 下游路由 | 默认边界 |
|---|---|---|---|
| 保留原版式增量编辑 | 用户要改字、补页、加备注/动画，认可原设计 | ppt-master / Edit Native PPTX | 不改母版、配色；页序默认不变，增删/重排须在修改方案中列明 |
| 保留内容重新设计 | 用户要“美化/换风格/更高级”，内容不变 | ppt-master / Beautify | 页数、页序、结论、数据不变；只改视觉 |
| 内容也要重新策划 | 用户要改结构、叙事、页数或结论 | 入口② | 先抽取大纲并重新确认 |
| 按公司模板重做 | 用户指定公司模板/品牌模板，内容来自源 PPT | 入口② → 分支 A | 先从源 PPT 抽取大纲并确认；不保留原版式 |

同一请求里既有视觉重做又有内容大改时，按“内容也要重新策划”处理，避免用 Beautify 偷偷改内容。

## 源文件处理

1. 先创建项目目录；把源文件复制到 `{项目目录}/sources/`（保留原文件名），只读保留。
2. 记录源文件绝对路径、页数、比例、标题、备注、动画、文件大小/修改时间或哈希。
3. 不覆盖、不改名、不移动原文件；成品永远写到新路径。多个源文件时按各自原文件名保存，不合并为一个来源。
4. 用户明确要求覆盖原件时，先保留带时间戳的备份并再次确认；默认仍输出到新文件。
5. 读取失败时请用户提供 PDF、逐页截图或文字稿；不猜测页面内容。
6. 解析结果（页数、逐页标题、备注、图片/图表概况）在需求确认前展示。

## 需求字段

复用 [intake.md](intake.md) 的主表，并补充以下字段；能从源文件和用户要求提取的标“材料提取”，只补问缺失项：

| 字段 | 要求 | 说明 |
|---|---|---|
| 源文件 | 必填 | 原文件绝对路径、`sources/` 下副本、页数、比例、是否含备注/动画 |
| 修改方式 | 必填 | 上方“修改方式”表中的一种；后两种转入口② |
| 修改范围 | 必填 | 全部 / 指定页码 / 指定章节；新增、删除、合并页单独列出 |
| 必须保留 | 必填 | 品牌、logo、配色、字体、法务文字、数据、页序、备注、动画；没有则写“无特别保留项” |
| 可改动项 | 必填 | 文字、版式、图片、图表、备注、动画；与“必须保留”冲突时先解决 |
| 验收标准 | 必填 | 未改动页保持原样（Beautify 时核对内容、页序、页数、数据不变）、指定页文字可编辑、页数符合修改方案、品牌元素齐全等 |
| 输出文件 | 必填 | 默认 `{项目目录}/{项目目录名}.pptx`；用户指定时按指定路径，源文件不被覆盖 |

输出固定为可编辑 PPTX，不展示 HTML 选项；沿用源设计，不重复询问“是否必须使用公司模板”，用户要求换成公司模板时转入口②。
目标、听众、时长可从原稿和用户要求提取；只补问缺失且影响修改的部分。纯视觉美化可以复用原稿的目标与听众，但仍要记录依据。

## 修改方案_确认版.md 模板

先在前台完整展示以下内容，用户确认后才保存。

```markdown
# {主题}｜PPT 修改方案

## 任务信息
- 源文件：{绝对路径}
- 源文件副本：{项目相对路径，只读}
- 源文件指纹：{SHA-256 / 大小+修改时间；用于交付前确认原件未被改写}
- 页数与比例：{源页数；16:9 / 4:3 / 其他}
- 修改方式：{保留原版式增量编辑 / 保留内容重新设计 / 按公司模板重做（转入口②）}
- 修改范围：{全部 / 指定页码 / 指定章节}
- 输出文件：{默认 `{项目目录}/{项目目录名}.pptx`；用户额外指定路径时一并列出}
- 必须保留：{品牌、logo、配色、字体、法务文字、数据、页序、备注、动画}
- 可改动项：{...}
- 整体验收标准：{未改动页保持原样、指定页可编辑、页数相符、品牌元素齐全等}
- 不改变：{明确不改的内容}

## 逐页修改清单
| 页码 | 当前标题 | 现状/问题 | 修改内容 | 保留项 | 验收标准 |
|---|---|---|---|---|---|
| P01 | {标题} | {现状} | {具体改法} | {保留项} | {可检查的结果} |

## 未改动页
{列出页码或范围；明确这些页保持原样。Beautify 全量重设计时写无，改为说明内容、页序、页数和数据保留规则}

## 新增/删除/合并页
{没有则写无；有则说明原因、影响和页序变化}

## 待补材料与风险
{只写影响修改成立的事项；没有则写无}

## 请确认
{集中列出需要用户决定的事项、拟保存路径；不重复调研已知信息}
```

设计规则一致时可按页型分组，但必须列出受影响页码；不能让用户自己猜哪些页会变。
源文件、修改方式、范围、保留项和逐页细节集中在 `修改方案_确认版.md` 维护，`需求调研.md` 只记录引用链接，不重复抄写。

## 确认

通用规则（什么算确认、分批展示、修订、草稿、快速模式）见 [confirmation.md](confirmation.md)。入口③额外要求：

- 前台展示完整需求与逐页修改方案；内容长时分批展示并标明进度。
- 明确说明确认后保存 `修改方案_确认版.md`、需求同步到 `需求调研.md`，以及是否继续制作。
- 确认版文末记录确认日期和用户确认依据。
- 新增/删除页、改结论、改页序、换模板或换输出格式，先展示差异并再次确认。

## 交接与检查

制作阶段的交接要求按 [production.md](production.md) 分支 F 执行，成品检查按其「三、成品检查」中的“入口③额外检查”执行。本文件不重复列出。
